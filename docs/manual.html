대관 예약 운영 매뉴얼

예약자 안내와 담당자 업무를 한 문서에 정리했습니다. 담당자는 하루에 한 번, 입금 내역과 관리 페이지를 맞춰 보면 됩니다.

1. 예약자가 하는 일 · 2. 요금 규칙 · 3. 담당자가 하는 일 · 4. 처음 설정 · 5. 문제가 생기면

1. 예약자가 하는 일

  1. 화면이 묻는 순서대로 하나씩 고릅니다. 위쪽 막대가 진행 정도를 보여 주고, 왼쪽 위 화살표로 이전 단계로 돌아갈 수 있습니다.
  2. 날짜: 달력에서 날짜를 누릅니다. 점이 있는 날은 이미 예약이 있습니다.
  3. 공간: 쓸 공간을 누릅니다. 여러 개를 함께 고를 수 있고, 5개 공간을 모두 쓰려면 "전체 통대관"을 누릅니다.
  4. 시간: 시작 시간과 종료 시간을 고릅니다. 최소 2시간부터이고, 아래 예약 현황표에서 비어 있는 시간을 볼 수 있습니다.
  5. 인원과 예약자: 이용 인원, 이름, 휴대전화 번호를 입력합니다.
  6. 확인: 일정, 요금 계산 내역, 입금할 금액을 확인하고 이용 안내 확인에 체크한 뒤 "예약하기"를 누릅니다.
  7. 입금: 금액과 입금 계좌가 나옵니다. 입금자명은 입력한 이름과 같아야 합니다. 24시간 안에 입금하면 담당자가 확정하고, 현황표에 "예약 완료"로 표시됩니다.

내 예약 확인과 취소

첫 화면 오른쪽 위 "내 예약"에서 예약번호와 휴대전화 번호를 입력하면 상태를 볼 수 있습니다. 입금 전 예약은 "예약 취소"를 누르면 바로 취소되고 시간이 다시 열립니다. 입금이 확인된 예약은 "취소 요청"으로 접수되고, 담당자가 확인한 뒤 환불 방법을 안내합니다.

현황표의 "입금 대기"는 다른 사람이 예약했지만 아직 입금하지 않은 시간입니다. 기한 안에 입금되지 않으면 다시 열립니다.

  • 시간당 요금의 합이 1일 요금을 넘으면 1일 요금만 받습니다.
  • 8시간을 넘으면 1일 요금에 남은 시간의 요금을 더합니다.
  • 최대 인원을 넘으면 1명당 10,000원을 더합니다. 여러 공간을 고르면 최대 인원을 합산합니다.
  • 요금은 서버가 다시 계산합니다. 화면에 보인 금액과 입금 금액은 항상 같습니다.

3. 담당자가 하는 일

관리 페이지 주소는 예약 페이지 주소 뒤에 /admin.html을 붙인 것입니다. 검색 엔진에 노출되지 않지만 주소를 공개하지 마세요. 처음 비밀번호는 Render의 ADMIN_PASSWORD 값이고, 들어간 뒤 설정 탭에서 바꿀 수 있습니다. 바꾼 비밀번호는 저장소에 암호화되어 저장되고, 이후에는 환경변수 값이 쓰이지 않습니다.

예약 목록

위쪽에 입금 대기 건수와 금액, 확정 건수, 이번 달 확정 금액이 보입니다. 상태별로 거르거나 이름, 전화번호, 예약번호로 검색합니다. 예약을 누르면 연락처, 인원, 이용 목적, 메모, 그 예약의 이력이 펼쳐집니다.

입금 확인

  1. "입금 대기" 필터에서 예약자 이름과 금액을 통장 입금 내역과 맞춰 봅니다.
  2. 예약을 펼쳐 "입금 확인(확정)"을 누릅니다.

취소

예약자가 취소를 요청하면 예약을 펼쳐 "취소"를 누르고 사유를 적습니다. 해당 시간이 바로 다시 열립니다. 환불은 통장에서 직접 처리합니다.

직접 등록

전화나 방문으로 받은 예약은 "직접 등록" 탭에서 넣습니다. 24시간 전 규칙은 적용되지 않고, 같은 시간에 이미 예약이 있으면 등록되지 않습니다. 입금을 이미 받았다면 "확정으로 등록"에 체크합니다.

취소 요청

예약자가 입금 확인된 예약의 취소를 요청하면 목록 위쪽 "취소 요청" 칸에 건수가 빨갛게 표시됩니다. 환불을 마쳤으면 "취소 승인(환불 후 처리)"을 눌러 취소하고, 취소하지 않기로 했으면 "취소 요청 반려"를 누릅니다. 입금 전 예약의 취소는 예약자가 직접 하므로 처리할 일이 없고 이력에만 남습니다.

달력

월간 달력에서 날짜별 확정과 대기 건수, 휴관일을 한눈에 봅니다. 날짜를 누르면 그날의 예약이 시간순으로 나옵니다.

휴관일

공휴일, 센터 행사, 공사처럼 예약을 받지 않을 날짜를 시작일과 종료일로 지정합니다. 사유가 예약 화면에 표시됩니다. 이미 예약이 있는 날을 지정하면 건수를 알려 주니, 예약자에게 직접 연락해 주세요. 해제하면 바로 다시 열립니다.

새 예약 알림

새 예약, 예약 취소, 취소 요청이 들어오면 슬랙, 디스코드 또는 텔레그램으로 알림이 갑니다. 설정 탭에서 연결 상태를 확인하고 테스트 알림을 보낼 수 있습니다. 연결 방법은 4장에 있습니다.

하루 업무 순서

관리 페이지는 1분마다 저절로 새로고침됩니다. 새 예약이나 취소 요청이 있으면 탭 제목과 "예약 목록" 옆에 건수가 표시됩니다. "입금 대기" 목록은 입금 기한이 급한 순으로 정렬되고, 6시간 안으로 남은 예약은 빨갛게 표시됩니다. 통장에서 입금을 확인했다면 목록의 "입금 확인(확정)"을 누르고 확인창에서 금액을 한 번 더 보고 승인합니다.

오시는 길과 지도

예약 화면 위쪽의 "오시는 길" 버튼을 누르면 주소, 교통 안내, 지도, "네이버 지도에서 열기", "카카오맵에서 열기", "주소 복사"가 있습니다. 열기 버튼은 설정 없이 바로 동작합니다. 화면 안 지도는 키를 넣은 만큼 탭이 생깁니다. 키가 없어도 구글 지도는 항상 나옵니다.

  • 네이버 지도: 네이버 클라우드 플랫폼(console.ncloud.com)에서 Application을 등록하고 Maps의 Dynamic Map을 선택합니다. 서비스 URL에 사이트 주소를 넣고, 발급된 Client ID를 Render 환경변수 NAVER_MAP_CLIENT_ID에 넣습니다.
  • 카카오 지도: developers.kakao.com에서 애플리케이션을 만들고, 앱 키의 JavaScript 키를 Render 환경변수 KAKAO_MAP_KEY에 넣습니다. 앱 설정의 플랫폼에서 Web을 추가해 사이트 주소를 등록하고, 카카오맵 사용 설정을 켭니다.

공간 사진

사진 파일을 public/photos 폴더에 room1-1.jpg, room1-2.jpg처럼 공간ID-번호로 이름 붙여 넣고 GitHub에 올리면 예약 화면 공간 카드에 나타납니다. 자세한 이름 규칙은 그 폴더의 README.txt에 있습니다.

이력

예약 접수, 직접 등록, 확정, 취소, 메모 수정, 비밀번호 변경이 시각과 함께 쌓입니다. 예약 기록이 지워진 뒤에도 이력에는 당시 이름, 일정, 금액이 남습니다. 목록 탭의 CSV 내려받기는 설정 탭에 있습니다.

기한이 지난 예약도 목록에 "기한 만료"로 남습니다. 늦게 입금이 들어왔고 그 시간이 비어 있으면 "입금 확인(확정)"으로 되살릴 수 있습니다. 다른 사람이 이미 예약했다면 확정되지 않습니다.

4. 처음 설정

  1. Vercel에서 GitHub 저장소 hundy0610/women을 Import합니다.
  2. Storage에서 Upstash Redis를 만들어 프로젝트에 연결합니다.
  3. Environment Variables에 ADMIN_PASSWORD, BANK_NAME, BANK_NUMBER, BANK_HOLDER, CONTACT_PHONE을 입력합니다.
  4. Deployments에서 Redeploy를 누릅니다.
  5. 알림을 받으려면 Environment Variables에 NOTIFY_WEBHOOK_URL(슬랙이나 디스코드의 웹훅 주소) 또는 TELEGRAM_BOT_TOKEN과 TELEGRAM_CHAT_ID(텔레그램 봇)를 넣습니다. 둘 다 넣어도 됩니다.
  6. 예약 페이지에서 계좌번호가 맞게 보이는지, 테스트 예약이 되는지 확인합니다. 테스트 예약은 관리 페이지에서 취소합니다.

요금, 운영 시간, 휴관 요일은 public/shared/config.mjs에서 바꿉니다. 현재 수요일과 일요일은 휴무라서 예약 화면에서 선택할 수 없습니다.

5. 문제가 생기면

증상원인과 조치
예약 데이터는 어디에 있나요Upstash Redis(console.upstash.com)의 Data Browser에서 볼 수 있습니다. 평소에는 관리 페이지에서 보면 됩니다. 이력은 log 항목에 쌓입니다.
"예약할 수 없습니다" 안내가 뜬다Upstash Redis가 연결되지 않았습니다. 4장 2번을 확인하고 Redeploy합니다.
계좌 정보가 설정되지 않았다고 나온다BANK_* 환경변수를 입력하고 Redeploy합니다.
관리 페이지에서 "비밀번호가 맞지 않습니다"ADMIN_PASSWORD 값을 확인합니다. 10분에 20번을 넘게 틀리면 잠시 막힙니다.
같은 시간에 두 건이 들어왔다발생하지 않도록 설계했습니다. 먼저 저장된 한 건만 성공하고 다른 쪽에는 "이미 예약이 있습니다"가 표시됩니다.
예약자가 입금자명을 다르게 입금했다예약자 연락처로 확인한 뒤 확정합니다.
